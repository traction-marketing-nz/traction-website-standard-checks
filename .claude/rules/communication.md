# Communication: ASD-STE100

Apply these rules to every chat reply: status updates, plans, error
explanations, questions, and step-by-step instructions.

Do not apply these rules to file content you write or edit. For files,
follow the project's content rules for that path.

If the user names a tone for a task ("marketing", "friendly", "formal
docs"), use that tone for the file content in that task. Chat replies
still follow these rules.

## Sentences

- Use short sentences. One idea per sentence.
- Instructions have a maximum of 20 words. Descriptive sentences can have up to 25 words.
- Use active voice.
- Use present tense for facts and instructions.
- Use the imperative for instructions: "Run the test", not "You should run the test".
- Put 1 instruction in each step.
- Do not use nested clauses. Split a long sentence into 2 or more sentences.
- Use "that" to start a relative clause. Do not omit it.
- Use a pronoun only when the noun it refers to is in the same sentence or the sentence before.
- Keep paragraphs short. Maximum 6 sentences in a paragraph.
- Use a heading for each topic when a reply has more than 1 topic.

## Words

- Use plain words. Do not use slang, idioms, metaphors, or jokes.
- Use common words: "use" not "utilise", "help" not "facilitate", "start" not "initiate".
- Use 1 word for 1 meaning. Use the same word for the same thing in every reply.
- Do not use vague words: "some", "often", "probably", "basically", "simply".
- Do not use "-ing" verb forms as nouns or adjectives ("configuring", "the running process"). Use "configure", "the process that runs".
- Do not use a noun as a verb ("to action", "to spec").
- Do not omit articles. Write "the file", "a session", not "file", "session".
- Do not use "there is" or "there are". Name the subject.
- Limit noun strings to 3 words. Write "the setup script for the cloud environment", not "the cloud environment setup script configuration".
- Use digits for numbers (1, 2, 3), not words.
- Define a technical term the first time you use it, in 1 short sentence.

## Modal verbs and person

- Use "must" for a requirement.
- Use "can" for an ability, an option, or a possibility.
- Do not use "may" or "might".
- Use "do not" for a prohibition.
- Use "you" for the reader.
- Use "I" only to describe your own action.

## Lists

- Give steps as a numbered list.
- Give options as a bullet list.

## Warnings and cautions

- Put a warning before the step it applies to, not after.
- Start a warning with a command: "Do not run this on main", not "Running this on main is dangerous".
- State the consequence in 1 sentence after the command.
